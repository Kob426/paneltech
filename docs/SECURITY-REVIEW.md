# Целевая проверка безопасности: вход, сессии и устройства

Дата: 22 октября 2026. Основа — версия `3d7d8f3`, затем изменения этого блока. Это review конкретных границ локального прототипа, **не полный пентест и не допуск к подключению клубов**.

## Выполнено

- [x] Проверены обработчики login/logout, сессии, роли/CSRF/Origin, enrollment, poll/results и отзыв устройств.
- [x] Лимит неудачных входов усилен: 10 отказов за окно 5 минут по IP **и** аккаунту. Смена forwarded IP не обходит account bucket; смена имени не обходит IP bucket. Проверены точная граница окна и ограничение памяти (2000 ключей без вытеснения живых записей).
- [x] Для неизвестного пользователя выполняется проверка dummy scrypt-хеша с тем же форматом. Это уменьшает очевидное различие вычислительного пути, но не доказывает постоянное время ответа.
- [x] Сессия отклоняется при `expires <= now`, истёкшая запись удаляется. Успешный повторный вход заменяет текущую cookie-сессию; независимые сессии сохраняются. Logout использует согласованные cookie attributes.
- [x] Проверены отзыв прежних сессий после изменения пароля и запрет оператору повысить свою роль. Пароли остаются salted scrypt; raw session/device tokens в БД не сохраняются.
- [x] Сохранены CSRF и проверка Origin; cross-site Fetch Metadata отклоняется даже без Origin. Эти заголовки не заменяют аутентификацию.
- [x] Security/cache headers применяются до JSON parser. Некорректный JSON получает безопасную ошибку 400 без фрагмента присланного тела; превышение 128 KiB — 413, а не 500. Неизвестные внутренние исключения получают общий ответ без деталей.
- [x] Device endpoint требует индивидуальный Bearer token корректного формата. Cookie сотрудника не авторизует агента, а device token не открывает панель. Проверены чужой job_id и немедленный отзыв poll/results.
- [x] Результат queued-команды отклоняется 409: сначала агент должен получить её через poll. Результаты running/unknown по-прежнему проверяют boot_id и фактический набор; повтор терминального результата остаётся идемпотентным.
- [x] Прежние проверки одноразового/просроченного enrollment, прав админа и запрета forwarded HTTP сохранены и прошли.

## Проверки

- `npm run typecheck` — пройден.
- `npm test` — **44/44**, включая девять новых security-тестов в `tests/security.test.ts` и прежние API/core/recovery-тесты.
- `npm run build` — пройден.
- `npm run test:browser` — Chromium проверяет, что изменения входа/сессий не ломают основной DEMO-сценарий и переключение сотрудников.
- `python3 tests/agent_smoke.py` — отдельный Linux .NET dry-run Worker проверяет регистрацию, polling, сдачу результата после выдачи, повторный запуск и отзыв. Это не настоящий Windows-ПК.

Новые тесты не печатают токены, пароли и переданные тела. Все базы/учётные записи — временные фикстуры, рабочая `.data` не очищалась. Зависимости/lockfiles и код Windows PowerShell этим блоком не менялись.

## Границы и оставшееся

- [ ] Rate limiter process-local: перезапуск сбрасывает окна; для нескольких API/публичного сервера нужны отдельная защита на ingress и согласованное хранилище лимитов. Возможна временная блокировка аккаунта намеренными неудачными входами — это компромисс прототипа, не полноценная anti-abuse система.
- [ ] TLS reverse proxy, очистка forwarded headers, разрешённые внешние host/origin, доверие сертификатов и управление секретами требуют отдельной эксплуатационной проверки. Локальные HTTP-тесты не подтверждают защищённый deployment.
- [ ] Нет полного анализа DoS, timing, всех браузеров, инфраструктуры, supply chain и скомпрометированного Windows-агента. Зарегистрированный агент остаётся источником сведений о своих правилах; сервер не проводит независимую аттестацию Windows.
- [ ] Не проверены реальные SCM/NetQos/GPO/UWF, подписи и доставка обновлений; ротация device token, полный audit log и восстановление утраченных credentials остаются в TASKS.
- [ ] Не выполнены fault injection .NET между receipt/действием/ответом, миграции/online-backup и нагрузка 50+ клубов.

Сервис не опубликован, реальные клубные ПК не подключались. Следующая работа выбирается из оставшихся пунктов этапа 4; найденные здесь исправления не закрывают все production-риски.
