## Что настроено

- `AGENTS.md`: компактная карта проекта, инструментов, команд и выбора навыка.
- `SOUL.md`: ясный рабочий стиль и честные границы утверждений. Это не переписанный системный промпт.
- `USER.md`: обращение «шеф» и подтверждённые требования пользователя; без выдуманного профиля и секретов.
- `DESIGN.md`: фактическая визуальная основа из CSS, принципы операторской панели и критерии будущего аудита. Контраст/клавиатурная доступность не объявлены автоматически пройденными.
- `skills/paneltech-development`: вертикальные изменения и экономная работа с контекстом.
- `skills/paneltech-ui-review`: задачи оператора, состояния, доступность, responsive и осмотр рендера.
- `skills/paneltech-verification`: выбор реально нужных проверок без подмены Windows Linux-тестами.
- `skills/paneltech-windows-agent`: protocol/QoS/manifest/outbox/TTL/boot и границы пилота.
- `skills/review-guides-and-skills`: повторяемая оценка вложений и внешних навыков.
- У каждого навыка `agents/openai.yaml`; `.agents/skills → ../skills` даёт одну файловую точку обнаружения вместо дубликатов.

Клиент должен перечитать skills для появления новых записей в своём UI; факт сохранения файлов сам по себе не подтверждает обновление UI-каталога. До этого AGENTS.md явно маршрутизирует к SKILL.md. Глобальные навыки других проектов не менялись.

## Применённые способы разумно расходовать контекст

1. Короткий AGENTS и ссылки на материалы по задаче вместо загрузки всей библиотеки.
2. Точные пути/rg и целевые участки вместо повторного чтения больших файлов.
3. Ограниченный полезный вывод с сохранением ошибок, полных диагностических логов и exit code.
4. Объединение независимых чтений, последовательность зависимых изменений/проверок.
5. Критерий готовности до реализации и выбор достаточного уровня тестов.
6. Долговременные факты в USER/PROJECT-STATUS, без постоянного дампа истории в контекст.
7. Простые проектные инструкции вместо дополнительных compress/proxy/auto-model/hook систем без доказанной необходимости.

Проценты экономии не заявляются. Модель, effort и service tier не менялись: пользователь их не выбирал, а доступные файлы не доказывают текущие runtime-значения.

## Проверка результата

Структура/YAML всех пяти навыков проверена официальным quick_validate.py OpenAI и локальным валидатором `node scripts/validate-agent-library.mjs`. Проверены локальные ссылки, UI metadata, отсутствие шаблонных TODO, команды npm и symlink в пределах checkout. Код приложения, зависимости, lockfiles, база и настройки реальных агентов этой задачей не менялись; полные API/браузерные/Windows-проверки ради Markdown повторно не запускались.

Применимость всех трёх PDF разобрана отдельно в [PDF-REVIEW.md](PDF-REVIEW.md). Сохранённые инструкции — проверяемые договорённости проекта, а не разрешение на публикацию сервиса или работу с настоящими ПК.
