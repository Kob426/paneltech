# Локальная панель с личным администратором

Этот режим предназначен для запуска на вашем компьютере: личные аккаунты и вымышленные клубы/ПК. Он не устанавливает Windows-службу, не меняет QoS, не подключает реальные компьютеры и не открывает сетевой доступ. Нужен Node.js 24 (версия проекта — 24.19.0); .NET и Python для обычного запуска панели не нужны.

## Первый запуск

Распакуйте исходники в отдельную папку и откройте в ней терминал. В Windows можно использовать командную строку или PowerShell; если PowerShell блокирует npm.ps1, вызывайте `npm.cmd` вместо `npm`, не меняя execution policy.

```sh
npm ci
npm run setup:owner
npm run local
```

В мастере введите **свой** логин (3–50 латинских букв, цифр, `_ . -`) и дважды пароль (12–200 символов). Пароль не отображается, включая символы-звёздочки. Это ожидаемо. Вводите каждое поле отдельно; отмена — Ctrl+C. Не передавайте пароль параметрами команд, через pipe или в переписке.

Откройте **http://127.0.0.1:3000** на том же компьютере. Поля входа пустые: используйте заданные вами данные. В этой базе создаётся только ваш администратор; публичные DEMO admin/operator не добавляются. Вымышленные ПК и заметная маркировка DEMO сохраняются.

`npm run local` выполняет сборку и запускает панель/API/симулятор. Если DEMO уже работает на порту 3000, сначала остановите его Ctrl+C. При следующих запусках выполняйте только эту команду; повторять мастер не нужно. Остановка — Ctrl+C. Удалённый доступ сотрудников с других компьютеров этим не развёрнут.

## Создать сотрудника

1. Войдите своим администратором.
2. Откройте **Управление → Сотрудники → Добавить сотрудника**.
3. Задайте уникальный логин и начальный пароль. Обычно выбирайте роль «Оператор»; «Администратор» даёт управление доступом/каталогом/клубами.
4. Нажмите «Создать пользователя». Передайте данные сотруднику отдельным согласованным способом; не помещайте их в отчёты, Git или скриншоты.
5. Отдельный браузерный профиль/приватное окно позволяет проверить вход сотрудника на том же ПК. Оператор выполняет операции/ведёт историю, раздела управления у него нет.

Сотрудники и история сохраняются в **`.data/local.sqlite`**. Публичный `npm run demo` использует другую базу `.data/demo.sqlite`; пилот — `.data/pilot.sqlite`. Личный локальный режим по-прежнему возвращает `realAgents=false` и не разрешает enrollment. Сочетание `--local` с `ENABLE_REAL_AGENTS=1` отклоняется.

## Сбросить пароль или отключить сотрудника

- Нажмите **«Сбросить пароль»** в строке сотрудника. Введите и повторите новый пароль, подтвердите завершение его сеансов, затем явно нажмите «Сменить пароль». Enter в поле не отправляет сброс; начальный focus — «Отмена».
- После подтверждённого сброса прежний пароль перестаёт работать, сеансы сотрудника отзываются. Ваша сессия сохраняется, роль и флаг отключения сотрудника не меняются. Для сброса используется отдельный password-only endpoint, поэтому несохранённый выбор роли не применяется попутно.
- При сетевом сбое запрос автоматически не повторяется. Поля пароля очищаются после попытки и при закрытии окна; ошибку показываем в диалоге. Пароль мог уже измениться: проверьте вход либо явно задайте другой после восстановления связи.
- Для отключения отметьте «Отключён» и нажмите «Сохранить» в нужной строке. Сеансы отзываются; история сохраняется. Нельзя отключить/понизить себя. Сброс своего пароля через новый диалог владельцу не предлагается — этот экран предназначен для сотрудников.

Мастер **не перезаписывает** существующую базу и не сбрасывает пароль владельца. Если пароль владельца утрачен, нужен другой действующий администратор либо отдельная процедура восстановления; удаление базы уничтожит аккаунты и историю. Защитите доступ к папке `.data` средствами ОС; полноценные Windows ACL/UWF этим блоком не настраивались.

При нестандартном DB_PATH одна и та же переменная должна быть задана для мастера и запуска. В CMD: `set DB_PATH=C:\PanelTechData\local.sqlite`, в PowerShell: `$env:DB_PATH='C:\PanelTechData\local.sqlite'`. По умолчанию переменные не нужны. Не направляйте мастер на DEMO/старую базу. Скопировать личную базу для обычного режима DEMO или пилота незаметно не получится — сервер требует запуск с `--local`.

## Что проверено

- 67/67 Node-тестов, включая шесть новых local-owner/API: единственный владелец/без стандартных аккаунтов, отказ перезаписи/неверных данных, роли/CSRF, сброс только пароля, отзыв нескольких сеансов, сохранность доступа владельца и отсутствие password в списке.
- Точные `npm run setup:owner` и `npm run local` выполнены в Linux на временной SQLite; setup работает через настоящий псевдотерминал. Проверена невидимость пароля в transcript, отказ pipe и защиты режимов. Регрессия обнаружила гонку echo перед prompt; скрытый режим теперь включается до вывода приглашения.
- `tests/browser_users.py`: личный вход без DEMO-подсказок, создание сотрудника и отдельный вход, отмена/Enter/Escape/focus, ошибки длины/повтора, подтверждённый сброс, отзыв сессии, потеря ответа после реального сохранения без replay, неизменность роли, отключение. Desktop/mobile диалог и PNG проверены.
- Чистая распакованная копия исходников: npm ci и тот же terminal/local smoke прошли с отдельной временной SQLite; это проверка передачи исходников в Linux, а не проверка Windows.
- Полный `bash scripts/check-web.sh`: typecheck, Node-тесты, build, прежние два Chromium-сценария и новый сценарий сотрудников.

Команды для повторной разработки здесь:

```sh
bash scripts/check-web.sh
python3 tests/local_owner_smoke.py
```

Вторая проверка использует Linux pty и не предназначена для Windows; для обычного запуска на ПК она не нужна. На настоящем Windows-ПК команды/TTY ещё **не проверены**. Также не проверены доступ из локальной сети/интернета, Windows QoS, SCM/UWF и реальные клубы. Все введённые в автоматических тестах аккаунты — временные фикстуры, не ваш персональный аккаунт. Свой аккаунт вы создадите мастером у себя.

На момент реализации этого блока GitHub и Actions были приостановлены. 24.10.2026 пользователь отдельно разрешил передачу текущей версии в GitHub с `[skip ci]`; Actions остаются на паузе. Проверки выполняются локально/в облачной среде.

## Резервная копия личной базы

`npm run db:backup -- --db .data/local.sqlite` работает при запущенной панели. Проверка, безопасное восстановление только в новый файл и миграция с предварительной копией — [BACKUP-RESTORE.md](BACKUP-RESTORE.md). Рабочий файл автоматически не заменяется; старые сеансы и доступы агентов из восстановленной копии отзываются.
