# Аварийные проверки агента в Linux

Стенд запускает **настоящий .NET Worker отдельным процессом**, убивает его через SIGKILL в заданных точках и запускает заново с тем же каталогом состояния. Действия выполняет отдельный файловый имитатор. HTTP отвечает временный loopback stub, а не сервер клуба. Никакие NetQos, PowerShell, SCM, UWF или реальные ПК не используются.

`tests/agent-harness/` — отдельный тестовый executable с project reference на агент. Он не входит в сборку/пакет агента и не добавляет тестовые флаги в production CLI. Перед отправкой симулированных инспекций требует loopback, имя TEST SIMULATION и специальный ответ stub. Обычный PanelTech API такого ответа не предоставляет. Код результата имитатора — `test_simulation`; он не является свидетельством маркировки Windows.

## Точная команда в текущей облачной среде

Из корня репозитория, после установки SDK через `bash scripts/setup-cloud.sh`:

```sh
export DOTNET_CLI_HOME=/tmp/paneltech-dotnet-home
export NUGET_PACKAGES=/workspace/.tools/nuget
/workspace/.tools/dotnet/dotnet restore tests/agent-harness/AgentHarness.csproj --locked-mode
/workspace/.tools/dotnet/dotnet build tests/agent-harness/AgentHarness.csproj --no-restore -c Release -m:2
python3 tests/agent_recovery.py
/workspace/.tools/dotnet/dotnet agent/bin/Release/net8.0/PanelTech.Agent.dll --self-test
python3 tests/agent_smoke.py
```

При системном SDK можно заменить абсолютный путь на `dotnet`. Новый стенд использует только Python stdlib, случайный свободный loopback-порт и временный каталог. Он завершает дочерние процессы и удаляет тестовое состояние. `agent_smoke.py` отдельно использует настоящий API с временной SQLite на порту 3101 и production Worker **без** `--enable-qos`; Windows-инспекция остаётся неподтверждённой.

## Покрытие

| Граница | Проверяемое поведение |
| --- | --- |
| SIGKILL после receipt до действия | После рестарта `unknown/process_interrupted`, ноль имитированных действий |
| SIGKILL после действия до сохранения результата | Одно имитированное действие; после рестарта unknown и чтение файлового состояния, без повторной мутации |
| SIGKILL после сохранения результата | Отправляется сохранённый результат, повторного действия нет |
| Stub принял результат и закрыл соединение без ответа | Идентичная повторная отправка outbox, одно действие |
| Повторная доставка job_id | Повторяется ответ из журнала, действие одно |
| Отзыв до poll и во время обработки, после сохранения результата | HTTP 401 завершает процесс с кодом 1; outbox остаётся недоставленным, автоматического enrollment нет |
| TTL уже истёк / истёк после receipt / локальные часы отстают | Действие не выполняется; учитывается время сервера и монотонное время ожидания |
| Смещение локальных часов ±120 секунд | `clock_skew`, ноль действий |
| Смена boot после crash и доставка старого boot | Нет повторения старого действия; старый receipt не помечается доставленным; некорректная новая доставка не загрязняет журнал |
| JSON null, неполная identity, неверный JSON, null/неполные receipt | Завершение с ошибкой до агентских POST, исходный файл сохранён |
| Утрата identity/journal, незавершённая первая запись `.tmp` | Нет автоматического сброса истории или новой регистрации |
| Повреждённый HTTP JSON и null exe | Нет действия; содержимое ответа/состояния и тестовый token не появляются в логах |

Итоговый набор: **19 тестовых методов**, включая варианты повреждения состояния и оба направления рассинхронизации внутри subtest. Отдельно 17 контрактных self-test и интеграционный Linux dry-run с настоящим API. Эти числа не означают исчерпывающего покрытия отказов.

## Изменённое поведение и восстановление

- `identity.json` и `receipts.json` проверяются до перезаписи и сетевой регистрации. JSON `null`, неполная/неверная identity, некорректные receipt и утрата журнала при сохранённом device token останавливают агент с `agent_stopped` и кодом 1. Содержимое файлов не печатается. При старой установке, которая ещё не получала заданий и не имела receipts.json, тоже требуется ручной разбор: автоматически считать историю пустой нельзя.
- При первой регистрации журнал создаётся заранее. C# запись использует временный файл, `Flush(true)` и rename. Старый целый основной файл имеет приоритет над оставшимся `.tmp`; если основного файла нет, `.tmp` не считается пустым состоянием. Атомарность каталогов/диска при отключении питания этим не доказана.
- Перед действием сравниваются локальные часы и `serverTime` с учётом монотонного времени запроса/ожидания. Смещение свыше 60 секунд отклоняется. Срок проверяется по более позднему времени: локальному либо серверному плюс всё прошедшее время poll/receipt. Медленный запрос может консервативно отклонить задание раньше, но не продлевает TTL. Это не защищает от намеренно ложного времени доверенного сервера; TLS и синхронизация часов всё ещё нужны.
- HTTP 401/403 останавливает Worker и host с кодом 1, сохраняя token и outbox для разбора. Неуспех сети/5xx сохраняет прежние ограниченные циклы повторов. Отзыв не отменяет уже начавшееся локальное действие мгновенно: агент узнаёт об отзыве при следующем запросе, уже действующие правила не удаляются.
- Старые boot receipt сохраняются недоставленными и не исполняются. Их очистка требует отдельной политики; бесконечный срок/объём хранения не решён этим блоком.

При остановке сначала остановить/не перезапускать службу автоматически, сохранить защищённую копию **всего** state и проверить историю на сервере. Не удалять receipts ради повторного выполнения. Восстановление допустимо только из согласованной целой копии identity + receipts + ownership, с локальной инспекцией перед новой командой. При утрате credentials администратор отзывает прежнее устройство и отдельно восстанавливает регистрацию. Ручное создание пустого журнала при неизвестной истории запрещено. Настройка SCM recovery, Windows ACL, дисковые ошибки, реальное питание, NetQos rollback и независимая серверная reconciliation в данном файловом стенде не проверялись; часть API reconciliation отдельно покрыта Node-тестами.
