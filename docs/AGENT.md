# Windows-агент: отдельный режим, установка и ограниченный пилот

**В рамках разработки ничего на клубные или личные Windows-ПК не установлено. Windows-служба, PowerShell NetQos, UWF и MikroTik в облачной Linux-среде не проверены. Не используйте DEMO-результаты как допуск к реальной сети.**

## Безопасные режимы

1. `--self-test` — локальные контрактные проверки, без регистрации и без QoS.
2. `--validate-job file.json` — валидация схемы задания на любой платформе, без регистрации и без системных изменений. TTL, boot/device consistency и список вариантов проверяются по переданным данным, а не подтверждаются живым Windows-ПК. Результат всегда `dry_run`, не технический успех QoS.
3. Worker без `--enable-qos` — регистрация/polling на специально подготовленном сервере, валидация полученного задания и ответ `dry_run`. Не выдаёт пустой набор за инспекцию Windows. Подходит для Linux локального стенда `tests/agent_smoke.py`.
4. **Только явный локальный аргумент `--enable-qos`** разрешает Windows cmdlet. Сервер не может включить этот режим заданием. На Linux этот флаг отвергается.

Операции только `health`, `inspect_rules`, `apply_marking`, `remove_marking`. В протоколе нет произвольного PowerShell, загрузки файла/игры, управления процессами, перезагрузки и UWF.

## Подготовка отдельного сервера пилота (не сделано автоматически)

Нельзя подключать реальный агент к DEMO. На отдельном локальном экземпляре API нужны отдельная БД, администратор и явный режим:

```sh
# Пример переменных; реальный пароль задайте через защищённые настройки окружения,
# не сохраняйте его в shell history, README или Git.
ENABLE_REAL_AGENTS=1 DB_PATH=.data/pilot.sqlite SECURE_COOKIES=1 npm run demo
```

При самом первом запуске дополнительно нужны `ADMIN_USERNAME` и `ADMIN_PASSWORD` (>=12 символов), введённые безопасным способом. После создания администратора их можно убрать. Открытые DEMO-пароли и симулированные ПК не создаются. На DEMO-базе пилотный режим откажется запускаться. `SECURE_COOKIES=1` предназначен для HTTPS; при исключительно loopback HTTP локальном контрактном стенде эту переменную не задают.

Для связи разных компьютеров отдельно настроить TLS reverse proxy с сертификатом, которому доверяет Windows-служба. Не отключать проверку сертификатов. API остаётся на loopback; proxy обязан очищать входные `Forwarded` / `X-Forwarded-*` и выставлять правильные `X-Forwarded-Proto`/`X-Forwarded-For`, Host. Входящий HTTP извне не разрешать. В текущем задании proxy, публичный DNS и публикация не создавались. Production-развёртывание требует отдельного review, см. PROJECT-STATUS.

Администратор создаёт клуб с согласованными вариантами, проверяет каталог и выбирает этот клуб. В «Управлении» выдаёт одноразовый enrollment-токен (10 минут). Он привязан к клубу; используется ровно один раз. Передавать через защищённый временный файл, не через аргумент с самим токеном или логи.

## Сборка

На машине сборки установить SDK 8.0.426 из официального источника; версия закреплена в `agent/global.json`. Из `agent`:

```powershell
dotnet restore --locked-mode
dotnet build --no-restore -c Release
dotnet bin/Release/net8.0/PanelTech.Agent.dll --self-test
# Для подготовки пакета Windows (в облаке не выполнялось):
dotnet publish -c Release -r win-x64 --self-contained false -o publish
```

Framework-dependent publish требует .NET 8 Runtime на Windows. Нужен весь output, включая `qos.ps1`, runtimeconfig и зависимости. Windows publish и установка службы остаются непроверенными; в облаке проверены Linux build и dry-run одного и того же исходного Worker.

## Консольный запуск Windows

Пример размещения: `C:\Program Files\PanelTechAgent` для неизменяемых бинарников/скрипта, `C:\ProgramData\PanelTechAgent` для state/config. Скопировать `agent/config.example.json` в конфигурацию; заменить serverUrl на HTTPS адрес согласованного стенда, stateDirectory — на абсолютный постоянный путь, name — на имя ПК. Конфигурация не содержит токенов.

State содержит `identity.json` (стабильный UUID + индивидуальный токен), `receipts.json` (outbox/дедупликация), `ownership.json` (точные собственные имена/игры/exe), `rollback.json` (последний собственный набор). Запись через временный файл и rename. Не редактировать/удалять manifest при действующих правилах. Потеря manifest приведёт к безопасному конфликту, а не присвоению правил по префиксу.

Ограничить ACL каталога state и файла enrollment: только локальные Administrators и выбранная учётная запись службы; запретить запись обычным пользователям. Пример для LocalSystem после проверки выбранных путей, в повышенном PowerShell:

```powershell
New-Item -ItemType Directory -Path C:\ProgramData\PanelTechAgent -Force
icacls C:\ProgramData\PanelTechAgent /inheritance:r
icacls C:\ProgramData\PanelTechAgent /grant:r '*S-1-5-18:(OI)(CI)F' '*S-1-5-32-544:(OI)(CI)F'
```

Токен enrollment записать в защищённый `C:\ProgramData\PanelTechAgent\enrollment.txt`. Первый запуск **без QoS**:

```powershell
& 'C:\Program Files\PanelTechAgent\PanelTech.Agent.exe' --config C:\ProgramData\PanelTechAgent\config.json --enrollment-file C:\ProgramData\PanelTechAgent\enrollment.txt
```

После подтверждённой регистрации остановить Ctrl+C и безопасно удалить enrollment-файл. При повторном запуске `--enrollment-file` не нужен: используются сохранённые ID и device token. Перезапуск процесса не создаёт новое устройство. Утраченный ответ регистрации до сохранения токена может потребовать отзыва созданного устройства и нового enrollment: автоматическое восстановление утраченных credentials не реализовано.

До разрешённого пилота не добавлять `--enable-qos`. Для одного согласованного свободного ПК:

```powershell
& 'C:\Program Files\PanelTechAgent\PanelTech.Agent.exe' --config C:\ProgramData\PanelTechAgent\config.json --enable-qos
```

Требования реального выполнения: Windows с модулем NetQos, Windows PowerShell 5.1 и повышенные права локального администратора. Команды проверяются заранее. `qos.ps1` — локальный фиксированный файл, а не полученный от сервера скрипт. Политика исполнения должна разрешать **проверенный/при необходимости подписанный** скрипт согласно правилам организации; агент не использует `ExecutionPolicy Bypass`. Подпись дистрибутива и процедуры доверия пока не реализованы. Не отключать антивирус, UWF, TLS или code signing для обхода ошибок.

## Windows Service (инструкция, не выполнено в облаке)

Для первого контролируемого пилота допустим LocalSystem: локальных прав достаточно для NetQos; такая привилегия требует защищённых бинарников/config/state. Для дальнейшего внедрения согласовать отдельную service account с минимальными достаточными правами и правом Log on as a service. Это не проверено в данном прототипе.

После успешного консольного пилота, остановив консоль (одновременно работает один процесс с lock-файлом), из повышенного PowerShell:

```powershell
$binary = '"C:\Program Files\PanelTechAgent\PanelTech.Agent.exe" --config "C:\ProgramData\PanelTechAgent\config.json"'
# Сначала служба в dry-run; добавление --enable-qos делается локально только после согласования.
sc.exe create PanelTechAgent binPath= $binary start= demand obj= LocalSystem
sc.exe description PanelTechAgent 'PanelTech outbound polling agent; dry-run unless explicitly enabled locally'
sc.exe start PanelTechAgent
sc.exe query PanelTechAgent
```

Автозапуск намеренно не требуется для первого пилота. `.UseWindowsService` включён в коде, но реальная Service Control Manager-интеграция не проверена. При переводе в реальный режим локально изменить binPath, явно добавив `--enable-qos`, с перезапуском службы. Не включать такой режим кнопкой браузера.

## Перезагрузка, UWF и хранение

NetQos `ActiveStore` не переживает перезагрузку. Агент определяет boot session через LastBootUpTime Windows, инспектирует текущее состояние и **не восстанавливает** исторические назначения. Требуется новая явная команда сотрудника.

Идентификатор и токен должны быть на согласованном постоянном хранилище. При UWF обычная запись в ProgramData может исчезнуть после reboot — сам путь **не гарантирует постоянство**. Установка в образ/постоянный том/согласованные исключения UWF выполняется отдельно после пилота. Агент не создаёт исключения и не выключает UWF. При утрате identity нельзя повторно регистрировать каждый boot без разбора: отозвать старую запись и исправить хранение. Receipt/manifest также должны переживать перезапуск процесса; при потере manifest не удалять чужие политики вручную по одному префиксу.

## Отзыв и удаление

1. Администратор панели: «Управление → Отзыв устройства». Устройство теряет доступ к poll/results; queued истекают, running становятся unknown. Отзыв не удаляет уже действующие правила Windows.
2. При необходимости сначала, пока доступ ещё есть и агент работает, выполнить явное удаление **собственных правил нужных игр**, подтвердить фактическое состояние. Если доступ уже отозван — локальная ручная инспекция уполномоченным администратором по точному manifest, без массового удаления QoS. Не удалять все NetQosPolicy.
3. Остановить и удалить службу:

```powershell
sc.exe stop PanelTechAgent
sc.exe delete PanelTechAgent
```

4. После проверки отсутствия действующих собственных правил и остановки процессов удалить бинарники и state по согласованной политике. Device token считать отозванным, историю на сервере сохранить. Само удаление службы/программы не является удалением QoS; ActiveStore исчезнет также после обычной перезагрузки, но агент не инициирует её.

## План ограниченного пилота и замер

Только после отдельного согласования: один свободный ПК, согласованный клуб, игра и варианты, доступ к локальному администратору и ручному восстановлению. До запуска сохранить перечень всех политик, проверить сторонние/общие exe и права, подписанный/проверенный агент, TLS, постоянство identity при UWF. Проверить dry-run, затем inspect, apply, повтор, switch, remove, частичный отказ/откат, потерю связи и reboot. Проверить GPO и фактические DSCP-пакеты, MikroTik-маршрут и пользовательские симптомы отдельно.

Для сравнения времени использовать одинаковый набор свободных ПК, игру, exe, вариант, начальные правила и критерии окончания. Отдельно измерить Mesh-терминал и панель: от выбора клуба до проверенных результатов на всех ПК; зафиксировать число ПК, ошибки, время ручного исправления, человеческую проверку симптома. Повторить несколько раз, не включать несопоставимые прогревы/установку. Шаблон — `docs/PILOT-MEASUREMENTS.csv`. Числа экономии и окупаемости не измерялись и не заявляются.
