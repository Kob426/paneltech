# PanelTech Agent — пакет Windows x64 для лаборатории

Это **неподписанный framework-dependent пакет для отдельного согласованного Windows-стенда**. EXE собран в Linux для win-x64; Windows/SCM/NetQos/ACL/NTFS/UWF и настоящая маркировка пока не проверены. Распаковка ничего не устанавливает, не создаёт службу, не подключает ПК и не запускает QoS.

## Что внутри и что требуется

Весь каталог нужен целиком: PanelTech.Agent.exe, PanelTech.Agent.dll, deps/runtimeconfig JSON, Microsoft DLL, фиксированный qos.ps1 (UTF-8 с BOM для Windows PowerShell 5.1), пример config.example.json, manifest.json, лицензия/уведомления. .NET Runtime не включён. Нужны **Windows x64 и Microsoft.NETCore.App 10.0.13 или новее в ветке 10.0.x x64** актуального servicing-выпуска; сборка использует SDK 10.0.402 и WindowsServices 10.0.13. SDK, ASP.NET и Desktop Runtime для обычного консольного агента не требуются. .NET 8 не заменяет .NET 10. ARM64/x86 этим пакетом не подтверждены.

Точные версии Windows клубных ПК пока неизвестны. Перед установкой сверить ОС и её поддержку с официальной таблицей .NET 10: https://learn.microsoft.com/en-us/dotnet/core/install/windows . Для настоящего QoS дополнительно нужны Windows PowerShell 5.1, NetQos cmdlet и права по согласованной политике. Не включайте ExecutionPolicy Bypass, не меняйте UWF и не отключайте проверку сертификатов. Подписание EXE/PowerShell и политика доверия организации остаются отдельной задачей.

## Проверить архив и состав

Сравните SHA-256 ZIP с полученным по доверенному каналу значением. В распакованном каталоге можно проверить все файлы в интерактивном PowerShell:

```powershell
$manifest = Get-Content .\manifest.json -Raw | ConvertFrom-Json
foreach ($file in $manifest.files) {
    $actual = (Get-FileHash -LiteralPath (Join-Path $PWD $file.path) -Algorithm SHA256).Hash
    if ($actual -ne $file.sha256) { throw "Checksum mismatch" }
}
dotnet --list-runtimes
.\PanelTech.Agent.exe --self-test
```

Контрольные суммы помогают обнаружить повреждение, но манифест внутри неподписанного ZIP сам по себе не подтверждает автора. Self-test не регистрирует устройство и не вызывает Windows QoS. **Эти команды не выполнялись на Windows в облаке**; для проверки пользователем нужен согласованный стенд. Python-верификатор исходников проверяет также безопасные пути ZIP, точный состав, PE x64, runtime/deps и отсутствие state/credential-файлов, без распаковки/запуска EXE.

## Первый запуск — только без маркировки

1. Проверить версию Windows/runtime, SHA архива и self-test. Подготовить отдельно разрешённый PILOT API с доверенным HTTPS и клубом. К обычному DEMO настоящий ПК не подключается. Это не разрешение подключать клуб в текущем этапе разработки.
2. Разместить **весь** пакет в защищённом каталоге бинарников, например C:\Program Files\PanelTechAgent. Пример конфигурации скопировать в C:\ProgramData\PanelTechAgent\config.json, state хранить отдельно в C:\ProgramData\PanelTechAgent\state. Пример содержит https://paneltech.invalid и CHANGE-ME — замените их на адрес согласованного стенда и имя этого ПК.
3. Проверить ACL: бинарники/скрипт изменяет только администратор, state/config/enrollment доступны только администратору и выбранной учётной записи агента. Хранение при UWF согласовать вручную; исключения пакет не создаёт.
4. Получить одноразовое разрешение регистрации в панели для выбранного клуба. Сохранить токен в защищённый временный enrollment.txt, не в командной строке, истории shell или config. Проверить, что state не скопирован с другого ПК.
5. Запустить в консоли без `--enable-qos`:

```powershell
& 'C:\Program Files\PanelTechAgent\PanelTech.Agent.exe' --config 'C:\ProgramData\PanelTechAgent\config.json' --enrollment-file 'C:\ProgramData\PanelTechAgent\enrollment.txt'
```

Проверить ID/имя/клуб в панели и результат dry_run, затем остановить Ctrl+C. Dry-run не подтверждает настоящую инспекцию или маркировку. После подтверждения регистрации защищённый enrollment-файл удалить; повторный запуск — только --config. При пропавшем ответе не выдавайте новую identity вручную: агент подтверждает сохранённого кандидата. На повреждённом state агент должен остановиться; сохраняйте файлы для разбора.

Сам пакет службу не создаёт. Установка службы, выбор account/ACL, её start/stop и проверка Windows-перезагрузки выполняются отдельным этапом. Сервер не может включить --enable-qos: в текущем этапе этот флаг не используется.

## Обновление с сохранением состояния

Сначала дождаться завершения операций; unknown требует отдельной сверки. Остановить консоль Ctrl+C или уже установленную службу, проверить её состояние STOPPED. Сохранить полный предыдущий пакет и защищённую копию config/state. Не удалять identity.json/receipts.json/ownership.json/rollback.json, не получать новый enrollment вместо обновления.

Распаковать новый проверенный пакет в отдельный каталог бинарников и переключить на него согласованный запуск, сохранив прежние абсолютные config/state. Не смешивать старые и новые DLL. Для перехода net8→net10 заранее установить совместимый .NET 10 Runtime. Сначала dry-run/проверка ID и журнала. Потеря ownership не даёт права присвоить существующие правила по префиксу; нужен разбор конфликтов.

Возврат прежнего бинарника **не откатывает Windows-правила**. Совместимость обратного перехода формата state автоматически не гарантируется: сначала остановить процесс, сохранить текущее состояние, проверить совместимость прежнего пакета. Восстановление более старого receipts-файла может потерять доказательство выполнения команды — вслепую такой откат не выполнять.

## Отзыв и удаление

Для согласованного устройства сначала отозвать доступ в панели и остановить процесс. Если служба ранее установлена, администратор проверяет её имя/путь, выполняет `sc.exe stop PanelTechAgent`, дожидается STOPPED и только затем `sc.exe delete PanelTechAgent`. Эти команды приведены для будущей ручной процедуры; пакет их не выполняет. До остановки проверьте незавершённые операции — отзыв не прерывает уже начатое действие мгновенно.

Удаление службы/бинарников **не удаляет QoS-правила**. Остаточные правила проверяются/удаляются отдельно только после разрешения и точного подтверждения ownership. Сохраняйте config/state/manifest до завершения разбора; не очищайте чужие политики. История остаётся в БД панели. Не удаляйте общий .NET Runtime автоматически: он может использоваться другими приложениями. Токены/копии state хранить защищённо и удалить после согласованного завершения разбора.
