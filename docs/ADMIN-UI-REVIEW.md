# Формы администратора и пустой каталог

Проверено в облачной Linux-среде через Chromium, viewport 1512×982 и 390×844. Новый сценарий `tests/browser_admin.py` входит в `npm run test:browser` и, через общий check-скрипт, в CI. Сервер и временная SQLite настоящие; все клубы, пользователи и ПК тестовые. Публикации и подключений Windows нет.

## Изменения

- Ошибка показывается внутри формы игры, клуба, создания сотрудника или изменения сотрудника; на ошибку переводится focus. Введённые значения сохраняются при отказе. Сервер остаётся окончательным валидатором.
- Названия проверяются после trim. Exe проверяются на формат, пути/аргументы, повторы без учёта регистра и предел 30 файлов. Пустая карточка игры по-прежнему допустима; apply/remove для неё недоступны.
- Варианты клуба требуют явного `ID:название`, ID 0–63 и уникальные ID. Отсутствие двоеточия не превращается в другое число. Кнопка «Новый» возвращает стандартный набор; после создания дальнейшее сохранение изменяет этот клуб и не создаёт дубликат.
- Создание сотрудника проверяет формат логина и длину пароля. Занятый логин показывается рядом с формой. При успешном создании пароль очищается. Выход, потеря сессии и смена пользователя очищают секретные черновики и выбор ПК, открывают вкладку компьютеров.
- При потере ответа POST запрос не повторяется. Черновик остаётся, сообщение предлагает сначала проверить список после восстановления связи. Если сервер подтвердил сохранение, но обновление списка не удалось, сообщение отдельно говорит, что изменение уже сохранено.
- Ошибка загрузки сотрудников имеет явную кнопку повторной загрузки. Запись, отзыв и выдача enrollment блокируются при отсутствии подтверждённой связи. В DEMO выдача enrollment по-прежнему недоступна.
- Пустой каталог имеет отдельное объяснение для администратора и оператора. Администратору доступен переход к созданию игры; операции с ПК заблокированы до появления игры. После добавления первая игра выбирается автоматически.
- Строки сотрудников переносятся на узком экране. Сетевой отказ не помечает корректные поля как неверные.

## Фактические проверки

| Сценарий | Доказательство |
| --- | --- |
| Пустой каталог | Игры удалены из отдельной seeded SQLite до старта обычного API; state действительно содержит пустой games. Проверены admin/operator, блокировка четырёх действий и переход к первой игре |
| Ошибки ввода | Пустое название, пути/повторы exe, неверный формат/range/повторы вариантов, неверные login/password; focus и сохранение значений |
| API 409 | Реальное создание сотрудника с занятым логином admin, затем успешное создание другого сотрудника |
| Неоднозначный результат сохранения | API реально сохранил игру, затем Playwright оборвал только ответ. Отправка одна, черновик сохранён, новая игра появилась в списке |
| HTTP 403, 503 и 401 | Контролируемые ответы Playwright для отказа изменения сотрудника, загрузки списка, записи клуба и потери сессии; checked локальное сообщение, retry, disabled controls и очистка секретного черновика. Это HTTP fault injection, не проверка нового серверного механизма авторизации |
| Desktop/mobile | Оба viewport, отсутствие горизонтального overflow и pageerror, расчёт контраста видимого текста выбранных состояний; итоговые PNG осмотрены |
| Общая регрессия | typecheck, build, 48/48 Node-тестов и прежний Chromium-сценарий массовых операций/связи/истории также прошли |

Четыре новых Node-теста проверяют неоднозначный ввод вариантов, соответствие разрешённого ввода серверным схемам, exe/имена и границы учётных данных. Серверные endpoint и контракты не менялись. .NET не менялся и в этом блоке не перепроверялся.

Рендеры создаются в `test-results/admin-{1512,390}.png` и `test-results/empty-catalog-{1512,390}.png`; каталог игнорируется Git, CI сохраняет только перечисленные PNG вымышленного DEMO. Для ручного запуска нужны установленные npm-зависимости, Playwright, Chromium и свободные loopback-порты 3099/3102:

```sh
npm run build
npm run test:browser
```

Полный WCAG/screen-reader аудит, Safari/Firefox, реальное мобильное устройство, Windows enrollment/отзыв/служба и первый удалённый Actions-прогон этим не подтверждаются. Настоящий агент не подключался. Остаются другие задачи этапа 4: неизвестные результаты при смене каталога, остальные дисковые/протокольные отказы и backup/migrations.
