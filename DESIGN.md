# PanelTech: дизайн-система рабочей панели

Назначение — быстро и безопасно выполнять операции поддержки клубов. Режим интерфейса — рабочий инструмент: читаемость таблиц, явные состояния и предсказуемые действия. Этот документ фиксирует существующий визуальный язык и критерии следующих изменений; он не заявляет, что аудит доступности уже пройден.

## Визуальная основа

Значения сверены с `web/src/style.css`. Сейчас они записаны в CSS литералами; переноса в CSS custom properties в этой задаче не было.

Палитра — исходная точка, не подтверждение контраста всех сочетаний. Проверять WCAG AA для конкретного размера/начертания: обычный текст 4.5:1, крупный 3:1; значимые границы/состояния интерфейса проверять отдельно. Серый мелкий текст и цветные badges нуждаются в таком аудите при доработке. Статус всегда передавать словами, а не одним цветом.

## Типографика, плотность, геометрия

- Текущий стек: Inter, системные sans-serif. Файл Inter не подключён, поэтому наличие этого шрифта не гарантировано; использовать доступный системный fallback. Новые шрифты при необходимости хранить локально с лицензией, без обязательного CDN.
- Текущие размеры: базовый текст 14px; h1 27px (mobile 22px), h2 17px, таблица 12px. Вспомогательные подписи местами 10px — это существующее ограничение, не рекомендуемый стандарт для важной информации.
- Для новых элементов ориентироваться на 14px и выше для основных действий/значимой информации; плотные таблицы допускают 12–13px после визуальной проверки. Не уменьшать шрифт ради помещения дополнительного текста.
- Использовать привычный ритм 4/8/12/16/24/32px, сохраняя соседние существующие значения, если правка не требует нормализации всей страницы.
- Текущие радиусы: поля/небольшие блоки 6–7px, панели 9px, модальные окна 12px. Тени сдержанные.
- Sidebar 240px на desktop, 205px при ширине до 1150px; при 700px и ниже навигация перестраивается сверху. Таблице разрешён собственный горизонтальный scroll.

## Структура экрана

1. Клуб и явная метка DEMO/PILOT.
2. Выбор игры/варианта и количество выбранных ПК.
3. Таблица ПК с доступностью, последней операцией и индивидуальной рекомендацией.
4. Результаты задания по каждому ПК, включая ошибку/откат/unknown.
5. История и отметки сотрудника отдельно от текущей инспекции.

Не скрывать подтверждение массовой операции за безымянной иконкой. Кнопка должна указывать действие и число ПК. Для группы не показывать одну рекомендацию, когда история различается. Старый снимок правил подписывать как кеш, не как текущую проверку.

## Формы, диалоги, состояния

- Сохранять связанный label и видимый focus. Для icon-only действий добавлять доступное имя.
- Объяснять disabled: нет выбранных ПК, не заполнены exe, вариант недоступен или недостаточно прав.
- При изменении диалога проверить начальный focus, удержание focus, Escape, возврат focus, доступный заголовок. Эти свойства не считаются реализованными одним role=dialog.
- Проверять пустую историю, offline, running, conflict, expired, unknown, отказ прав, частичный сбой, неуспешный откат, сетевую ошибку и длинные значения.
- Не закрывать неуспешный результат зелёным toast. Не называть unknown ошибкой применения: изменение могло произойти, ответ — потеряться.

## Текст, иконки, движение

Русские конкретные подписи: «Применить к 6 ПК», «Команда пропущена: ПК недоступен», «Результат неизвестен: нужна инспекция». Технический статус, слова сотрудника и проверка пользовательского симптома — разные сведения.

Новые иконки брать из одного согласованного SVG-набора с лицензией; текстовое состояние сохранять. Не подключать React-библиотеку в Vue ради одного эффекта.

Движение только поясняет изменение: короткая обратная связь/переходы примерно 120–200ms, по возможности opacity/transform. При добавлении учитывать prefers-reduced-motion. Без scroll hijacking, видео-фонов, навязчивых курсоров, GSAP/3D по умолчанию и эффектов, задерживающих оператора.

## Критерий проверки

Функциональный путь должен работать с настоящим локальным API; desktop 1512px и mobile 390px проверяются в Chromium. Осмотреть рендер, клавиатуру, контраст и ошибки; один screenshot не доказывает доступность. Команды — `skills/paneltech-verification/SKILL.md`. В этой задаче интерфейс не переделывался; зафиксированы правила будущих изменений.
