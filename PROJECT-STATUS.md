- Вынесен клиент API: checking/online/offline/reconnecting, 6-секундный timeout и время последнего ответа. При отсутствии подтверждённой связи мутации не отправляются, данные подписываются как последний снимок. POST автоматически не повторяется; при потерянном ответе предлагается проверить историю.

## Практические ограничения

Прототип использует SQLite v5: защищённый журнал действий и JSON records с внутренними ссылками на общие сжатые BLOB-снимки, журнал транзакционных миграций и частичные expression index. История автоматически не удаляется; API возвращает полные массивы. Online backup и изолированное восстановление проверены в Linux; расписание/retention и локальное наблюдение добавлены в 4.38. Шифрования, off-site и внешнего мониторинга нет. History отдаётся страницами, завершённая история в state ограничена; все клубы/игры/устройства и незавершённые ещё могут увеличивать ответ. Горячие Core/agent операции читают индексы active/due/device; workspace ограничен клубом. Глубокая история/метаданные и unscoped ответы всё ещё могут расти. Очередь рассчитана на один процесс API. Полной транзакции Windows нет: откат best effort, результат отдельно отражает остаточные/неизвестные изменения. При аварии процесса/питания автоматический откат или восстановление из истории не запускается. Нужно проверять состояние и выдавать новую явную команду.

Просроченные/старые boot-команды не выполняются; unknown блокирует новые действия до сверки. Агент и сервер требуют синхронизированных часов; смещение свыше 60 секунд отклоняется с clock_skew, TTL учитывает время сервера и монотонное ожидание. Последний снимок правил с просроченной инспекцией показывается как кеш, а не текущее подтверждённое состояние. Отметка сотрудника «помогло» остаётся исторической подсказкой после reboot и смены каталога.

Windows-политики с общими/wildcard-условиями могут консервативно блокировать применение. При потере manifest собственность не угадывается по префиксу — нужен разбор конфликта администратором. Обновлённый агент подтверждает сохранённого кандидата после потерянного ответа регистрации/смены. Потеря identity/receipts/ownership требует явного device-bound восстановления с карантином; автоматического сопоставления полностью утраченного state с физическим ПК нет.

Агент переведён на .NET 10 LTS (SDK 10.0.402 / servicing 10.0.13, поддержка до 14.11.2028). Совместимость конкретных Windows и процедуры установки/publish/службы ещё требуют лаборатории; версий ОС клубных ПК пока нет. Windows Service запускается только по отдельной инструкции и не устанавливается автоматически. В DEMO нет способа включить реальный QoS кнопкой; нужен отдельный пилотный сервер/база и локальный `--enable-qos`.
