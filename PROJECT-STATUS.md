## Что работает

- Русский интерфейс Vue: вход → список клубов/ПК → выбор игры и варианта → массовое/одиночное действие → индивидуальные результаты → история.
- Два вымышленных клуба, по шесть ПК со стабильными ID. DEMO заметен в панели и каждой записи результата. Настоящие агенты в DEMO отключены.
- Применение/переключение/удаление собственных правил симулятора; инспекция и health. Офлайн пропускается, остальные ПК продолжают работу.
- Сценарии нет прав, сторонний конфликт, несовместимые общие exe, частичный отказ с откатом, потеря ответа unknown и отдельная сверка, имитация reboot без восстановления правил.
- Сохранение заданий, результатов, каталога, пользователей, сессий и отметок в SQLite. История и отметка «помогло» переживают перезапуск API и видны другому сотруднику.
- Администрирование клубов/вариантов, каталога/ревизий и пользователей; разграничение operator/admin.
- .NET-агент: консольный Worker/код Windows Service, исходящие запросы, ограниченные циклы повторов, enrollment, стабильная identity, индивидуальный отзываемый token, receipt/outbox, TTL/boot_id/дедупликация, dry-run.
- Отдельный фиксированный PowerShell-обработчик NetQos с ActiveStore, проверкой прав/cmdlet, точным ownership manifest, обнаружением конфликтов, чтением результата и попыткой компенсирующего отката. **Его реальное выполнение ещё не проверено.**

## Не выполнено и не подтверждено

- Windows publish/runtime, установка/удаление службы SCM, Windows PowerShell 5.1 и выполнение cmdlet NetQos. Linux-сборка и dry-run этого не доказывают.
- Фактическое применение/удаление DSCP, считывание свойств на разных версиях Windows, влияние GPO, системный rollback при реальных сбоях/потере питания, подпись пакета и скрипта.
- Постоянство identity/token/manifest под реальным UWF. Исключения UWF не создавались, защита диска не отключалась.
- MikroTik, реальный маршрут/пакеты/пинг/голосовой чат, действительные exe PUBG/актуальный аудит Fortnite. Успех симулятора не свидетельствует ни об одном из них.
- Развёртывание HTTPS proxy и проверка доверия сертификатов на Windows. Сервис слушает только loopback, публичный сервис/туннель не создан.
- Нагрузочный тест 50+ клубов, несколько процессов API, ротация token, восстановление утраченного ответа enrollment, полноценный неизменяемый аудит и production hardening.
- Измерение времени Mesh против панели и экономическая оценка: данных нет, цифры не придуманы.

## Практические ограничения

Прототип использует простую JSON-record схему SQLite и отдаёт все записи state/history без пагинации. Очередь рассчитана на один процесс API. Полной транзакции Windows нет: откат best effort, результат отдельно отражает остаточные/неизвестные изменения. При аварии процесса/питания автоматический откат или восстановление из истории не запускается. Нужно проверять состояние и выдавать новую явную команду.

Просроченные/старые boot-команды не выполняются; unknown блокирует новые действия до сверки. Агент и сервер требуют синхронизированных часов. Последний снимок правил с просроченной инспекцией показывается как кеш, а не текущее подтверждённое состояние. Отметка сотрудника «помогло» остаётся исторической подсказкой после reboot и смены каталога.

Windows-политики с общими/wildcard-условиями могут консервативно блокировать применение. При потере manifest собственность не угадывается по префиксу — нужен разбор конфликта администратором. Если ответ enrollment потерян до сохранения токена, нужна процедура отзыва и повторной регистрации, автоматического восстановления credential пока нет.

.NET 8 выбран для прототипа и заканчивает поддержку в ноябре 2026; перед production нужен переход на поддерживаемый LTS. Windows Service запускается только по отдельной инструкции и не устанавливается автоматически. В DEMO нет способа включить реальный QoS кнопкой; нужен отдельный пилотный сервер/база и локальный `--enable-qos`.

## Запуск и следующий шаг

Из корня: `npm ci`, затем `npm run demo`. Панель/API/симулятор вместе, loopback port 3000. Учетные записи и сценарий — в README.

Ближайший шаг после сохранения кода в Git — завершить этап 4 из TASKS.md: воспроизводимость, доступность/связь UI и дополнительные сценарии ошибок. Затем нужна отдельно согласованная Windows-лаборатория. Пилот на одном свободном клубном ПК возможен после неё, с ручным восстановлением, TLS и согласованным постоянным хранением при UWF. Порядок установки/отзыва/удаления и замера времени — `docs/AGENT.md`. Настоящий клуб не подключался; текущая задача не разрешает такое подключение.

Инструкции установки и запуска облачной среды сохранены отдельно как draft `install_script` / `start_skill`. Сохранение draft не является публикацией окружения и не доказывает восстановление в новой задаче.
