# Рабочая панель поддержки

Прочитать `DESIGN.md` из корня и текущие `web/src/App.vue` / `web/src/style.css`. Сохранить существующий визуальный язык при уточняющей правке; новый визуальный стиль вводить только в рамках задачи на редизайн.

## Порядок

1. Определить задачу сотрудника на экране: выбрать клуб/ПК, применить вариант, разобрать ошибку или найти прежнее решение. Для новой страницы выписать основной и ошибочный путь.
2. Показать ясную иерархию: контекст клуба → выбор ПК → игра/вариант → явное действие → результат по ПК. Не превращать операторскую панель в рекламный лендинг.
3. Сохранить число выбранных ПК и состав массовой операции в подтверждении. Не смешивать разные рекомендации в одну для группы.
4. Проверить initial/loading/empty/success/error/disabled/expired/unknown, длинные имена, отсутствие exe, недоступный вариант, офлайн и устаревшую инспекцию. Цвет сопровождать текстом.
5. Проверить клавиатуру: labels, tab order, видимый focus, доступное имя кнопок/checkbox, Escape и возврат фокуса у диалога при реализации/изменении диалога. Не считать текущий UI полностью доступным без проверки.
6. Воспроизвести действие реальным API. Проверить desktop 1512px и mobile 390px: таблице допустима своя горизонтальная прокрутка; основной экран и действия не должны пропадать за viewport.
7. Проверить читаемость, контраст, плотность строк, переносы, наложения и кликабельные области на рендере Chromium. Запустить подходящий browser smoke через [навык проверки](../paneltech-verification/SKILL.md).
8. Снять итоговый скриншот после связанных правок и осмотреть. Отчёт отделить на исправленное / обнаруженное / непроверенное.

## Тон и моушен

Писать конкретно: «Применить к 6 ПК», «ПК недоступен: команда пропущена», «Результат неизвестен: нужна инспекция». Успех QoS не называть улучшением пинга. Декоративные эмодзи не использовать как единственную иконку состояния; при добавлении библиотеки SVG проверить Vue-совместимость и лицензию. Микроанимации делать короткими и необязательными, учитывать prefers-reduced-motion. GSAP, 3D, scroll hijacking и видео вводить только для обоснованной отдельной задачи, не по умолчанию.

## Примеры преобразований

- «Всё готово!» → «DEMO: набор симулятора совпал; сеть Windows не проверялась».
- Общая «рекомендация 40» для выбранной группы → дата/причина/вариант в каждой строке ПК.
- Зелёный значок без подписи → текстовый статус и цвет, unknown отдельно от failed и succeeded.

Источники решений и непринятые советы: `docs/AGENT-AND-SKILLS-AUDIT.md`, `docs/PDF-REVIEW.md`.
