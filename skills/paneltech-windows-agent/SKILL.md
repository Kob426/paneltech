# Агент и граница реального исполнения

Прочитать `docs/AGENT.md`, `ARCHITECTURE.md`, `agent/Contracts.cs`, `agent/Worker.cs`, `agent/Qos.cs`, `agent/qos.ps1` и затронутый серверный endpoint. Проверить актуальную официальную документацию Microsoft для изменяемого поведения NetQos.

## Инварианты

- Принимать только health, inspect_rules, apply_marking, remove_marking; запрещать удалённый текст команды/PowerShell, пути/аргументы вместо имён exe.
- Проверять device_id, boot_id, TTL, game_id, список exe и разрешённые варианты и в API, и на агенте.
- Сохранять стабильную identity и индивидуальный token на согласованном постоянном хранилище, доступном службе; UWF-исключения не создавать автоматически.
- Enrollment одноразовый и ограниченный сроком, клуб назначает администратор. Одна identity не должна превращаться в несколько ПК после перезапуска процесса.
- Записывать receipt до действия, результат до отправки, delivered после подтверждения. Повтор job_id не должен повторять мутацию. Не обещать exactly-once.
- При потере связи после изменения показывать unknown; разрешать его только отдельной фактической инспекцией. Dry-run не даёт фактической инспекции и не подтверждает технический успех QoS.
- Менять только собственные правила конкретной игры в ActiveStore. Владение устанавливать точным manifest, не одним префиксом. Старые сторонние политики и несовместимые общие exe давать как conflict.
- Сохранять предыдущий собственный набор, проверять ожидаемый фактический набор и результат компенсации. Откат best effort; отражать неизвестность и остаточные изменения.
- После reboot инспектировать состояние, не восстанавливать историю без новой команды сотрудника.

## Рабочая процедура

1. Воспроизвести проблему сначала контрактным тестом/изолированным Linux dry-run, если это возможно.
2. Сверить C#/TypeScript/PowerShell поля, nullable, типы и коды результатов. Пример ранее найденной интеграционной ошибки — rollback:null из C# против optional string API.
3. Сделать изменение, выполнить [подходящие проверки](../paneltech-verification/SKILL.md), обновить ограничения в PROJECT-STATUS.
4. Для Windows-проверки подготовить конкретный план и требования, но не подключать реальный клуб, не устанавливать службу и не включать --enable-qos без отдельного явного поручения.
5. Держать .NET lifecycle и совместимость SDK на виду; `.NET 8` заканчивает поддержку в ноябре 2026. Не обещать production-готовность только по Linux build.

Запрещено автоматически отключать защиту диска/сертификатов, перезапускать игры/ПК и расширять интерфейс до произвольного remote execution. Проверка QoS не подтверждает маршрут/пинг/голос; пользовательский симптом проверяется отдельно в пилоте.
