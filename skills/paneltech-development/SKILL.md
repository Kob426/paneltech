# Разработка PanelTech

1. Из корня checkout прочитать AGENTS.md, USER.md, нужный пункт Codex_Marking_MVP.md и актуальный PROJECT-STATUS.md. Проверить git status.
2. Найти путь поведения через `web/src/App.vue` → `server/app.ts` → `server/core.ts` → `server/store.ts`; контракты лежат в `shared/contracts.ts`, агент повторяет их в `agent/Contracts.cs`.
3. Сформулировать конкретное наблюдаемое поведение и критерий готовности. Для небольшой правки достаточно одного предложения; не создавать формальный план ради формы.
4. Реализовать минимальную связную вертикаль с серверной валидацией и понятным русским результатом. Не заменять API статическими данными. При изменении протокола проверить обе реализации контрактов.
5. Сохранять снимок игры/exe/ревизии/варианта в истории; рекомендации брать только из пользовательского «помогло» для точного device+game. Удалённый клубный вариант не разрешать из истории.
6. Сохранять раздельные DEMO/PILOT базы, стабильную identity, срок и boot_id команды, независимые результаты массовых заданий, сериализацию мутаций и явное unknown при неопределённости.
7. Не скрывать первопричину за ретраем. Каждый повтор должен следовать диагнозу или изменению предпосылки. При дефекте читать сообщение ошибки и целевой участок, а не весь проект заново.
8. Выбрать проверки через [навык проверки](../paneltech-verification/SKILL.md). Для правок UI также прочитать [навык интерфейса](../paneltech-ui-review/SKILL.md).
9. Обновить документацию только в затронутой части. Сообщить реализованное поведение, выполненные проверки и оставшиеся ограничения.

## Экономная работа с контекстом

Искать через rg; загружать подходящие файлы/навыки по мере необходимости. Объединять независимые чтения. Показывать итоги тестов и относящиеся к ошибке строки; сохранять exit code. Передавать между сессиями состояние через TASKS/PROJECT-STATUS, не через дампы переписки. Не менять модель/effort/плагины ради неподтверждённых процентов экономии. Не запускать делегирование, если задача и применимые инструкции его не предусматривают.

## Примеры

- «Добавь фильтр истории по игре»: проверить API query, UI фильтр, серверный тест и существующий браузерный сценарий.
- «После reboot команда применена повторно»: воспроизвести boot/TTL/receipt, исправить обе стороны затронутого контракта, добавить регрессию, не маскировать её автоматическим восстановлением правил.
